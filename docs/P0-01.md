# P0-01：一次性模拟任务

本阶段仅运行 Python 固定模拟函数。没有 Codex、Worker、OpenAI SDK、模型请求、API Key 或任意用户命令执行入口。

## 发布前批准边界

RELEASE-02 授权仅发布手动测试版本：工作流只有 workflow_dispatch，没有定时或其他自动触发入口。创建远端 codex-state 分支、首次在线触发以及以后恢复自动调度，仍需用户另行批准。不能覆盖 feat/interactive-math-v1 或其部署工作流。

未来运行所需的 contents:write 仅用于控制器写 codex-state，不修改仓库权限设置。使用短期 GITHUB_TOKEN，无须 PAT 或任何新增 Secret。若现有仓库策略禁止写入，报 BLOCKED，不自行改策略。

## iPhone 注册（仅发布获批后）

1. 在 GitHub 网页打开 Actions → P0-01 one-time simulator → Run workflow，选择默认分支。
2. operation 选 register，task_id 输入唯一 ID，例如 demo-001。
3. 一小时后执行：delay_minutes 输入 60，run_at 留空。
4. 绝对时间：delay_minutes 留空，run_at 输入带时区 ISO 时间，如 2026-10-27T18:00:00+08:00。两者必须且只能填一个；允许未来 30 天。
5. simulate_failure 通常保持 false；验收失败路径时才勾选。
6. 注册运行成功后，查看 codex-state 分支 README.md，核对计划 UTC 时间。可关闭手机和电脑。

延迟以控制器接受注册的时间起算。注册只登记，不立即执行。本手动版本不会在到期后自行运行；必须再次手动运行 operation=check。到期前检查不会执行，到期后检查只执行一次；重复检查不重跑。

本版本未启用 cron。将来若获批启用，GitHub cron 是尽力调度，可能延迟或丢失，不保证精确到秒或最迟完成时间；公开仓库长期无活动可能停用定时器。定时工作流必须存在于默认分支。

## 持久状态及执行记录

codex-state 是独立、无父提交初始化的状态分支，包含：

- p0-01/state.json：任务及状态；计划、注册、触发、认领、完成时间和 Actions run ID。
- README.md：可在 iPhone 直接阅读的结果和 Actions 链接。

触发时间采用 GitHub run.created_at，是可观察的运行创建时间；不将其误称为 cron 精确触发时刻。认领时间为控制器运行时刻。

Actions Summary 显示结果；p0-01-<run-id>-<attempt> artifact 保存 JSON/Markdown 30 天。失败时尽力保存诊断；硬取消、runner 丢失或存储故障不能保证 artifact 上传。持久认领仍可供恢复核对。状态分支只追加正常提交，不 force push、不合并到业务分支、不部署。

## 防重及失败恢复

仓库级固定 concurrency group，cancel-in-progress=false；GitHub 可能替换尚未启动的 pending run，因此提交注册表单不代表已注册，必须确认注册运行成功及状态文件。若注册运行被取消，可用原 ID 重新注册；已存在 ID 必定拒绝覆盖。

写入通过 GitHub Git Data API 创建以预期 SHA 为父提交的状态提交，再 force=false 更新 ref。并发者形成 sibling commit，只有一个可以 fast-forward。认领持久成功后才调用模拟函数；状态冲突、权限错误、网络结果不明均立即停止，不重试。

pending → claimed → succeeded/failed。succeeded、failed 和 claimed 均不再执行。后续 check 发现旧 claimed 对应 Actions 运行已结束，只记为 failed，不重新认领。仍在运行、状态查询失败或同 run ID 的重跑保持 claimed。终态不明的错误明确保留人工调查入口。

这是自动最多一次执行，不保证故障下任务一定执行。认领失败时模拟函数不运行；成功认领后崩溃可能导致零次执行。完成记录保存失败可能出现模拟已运行但仍 claimed，恢复时标记不确定失败，不重复。需要重试时，由用户审核旧记录后另建新 task_id；不得编辑状态把旧任务改回 pending。
